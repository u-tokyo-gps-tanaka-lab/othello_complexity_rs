# 学習した評価による逆ビーム探索の実験

2026年10月25日に、合法棋譜から前駆局面の順位を学習し、その評価を逆ビーム探索に組み込んだ。**今回の小規模実験では、独立144局面に対してGBFSの成功75件を維持し、1件を追加で証明できた。生成候補数は0.47%減ったが、実行時間の安定した短縮や、実際のSAT残存集合での探索量削減は確認できなかった。** 通常のGBFSを置き換える根拠にはせず、実験用の追加方式として提供する。

到達可能性の判定に学習出力を使わないことを最優先にした。学習探索が返せる結果は、合法棋譜を再生検証した `OK` と、未確定の `UNKNOWN` だけである。幅制限がなかった場合や、前向き表との不一致で終わった場合も、学習探索から `NG` は返さない。

## 判定の根拠

モデルは候補の順位だけを決める。[公開API](../../src/search/beam.rs)は、内部探索が返す `NotFound` も必ず `Unknown` に変換する。CLIとベンチマークにも、学習探索から `NotFound` が出たらエラーにする検査を置いた。モデルの点数や、学習した確率に閾値を設けて到達可能・到達不能を断定する処理はない。

成功は、既存の `core::found` が作った証明棋譜を再生して確かめる。CLIでは `solve_query` による再検証も行う。前向き表との一致、絶対手番、合法着手、強制パス、終局後の不正なパスの扱いは既存の規則に従う。最終実験の全成功証跡は、ビットボード実装を呼ばない[独立した配列盤面の検証器](../../scripts/verify_records_independent.py)でも再生した。

モデルはJSONを1回読み込み、スキーマ、特徴量の版、配列の形、有限性、重みの範囲を検査する。隠れ層は最大128ユニット、各パラメータの絶対値は最大1,000,000に制限する。入力特徴量はすべて0以上1以下なので、受理したモデルの推論が浮動小数点の範囲を超えない。標準初期配置以外からの学習探索は明示的に拒否する。不正なモデルは分類結果ではなくエラーとなる。[モデルの実装](../../src/search/learned.rs)を参照。

これらは、モデルの予測が外れたときに探索成功率が下がることを許容しつつ、予測を判定の証拠にしないための設計である。全既存ソルバの形式的な正しさを証明したという主張ではない。

## 学習とモデルの選択

学習用に1,000棋譜、学習の検証用に別の200棋譜を生成した。12〜56石を4石刻みで取り出し、実際に観測した前駆局面を、最大7個の比較候補より上位に置くように学習した。比較候補は、厳密な逆着手の組合せから重複なしで抽出し、正方向の再生と既存の必要条件を通過したものを使う。比較候補は未確認の別経路であり、到達不能の負例ではない。

入力は相対盤面の2つの64要素ビット平面と、絶対手番、合法手数、隣接関係など32個の有界な特徴量からなる。線形モデルと、隠れ層16ユニットのReLUネットワークを比較した。学習目的は、観測前駆を $p$、比較候補を $c$、評価を $r_\theta$ とする

\[
\log\bigl(1+\exp(r_\theta(c)-r_\theta(p))\bigr)
\]

の最小化である。この評価値は到達可能性の確率ではない。

| 項目 | 学習用 | 学習の検証用 |
|---|---:|---:|
| 元棋譜 | 1,000 | 200 |
| 比較群 | 11,426 | 2,271 |
| 候補行 | 78,671 | 15,552 |
| 観測前駆の行 | 11,430 | 2,271 |

棋譜単位で分割し、固定初期配置を保存する4対称変換を使って重複を調べた。検証用から学習用と重なる26群を除外し、正規化した目標・候補局面の重複を0にした。候補の抽出上限128に達した群はなかった。学習用・検証用の全1,200棋譜は、既存実装と独立実装の双方で再生できた。

両モデルを30エポック学習し、学習の検証用データで順位損失が最小のエポックを保存した。線形モデルは30エポック、ネットワークは19エポックが選ばれた。検証順位損失はそれぞれ0.527161、0.506344、観測前駆が比較群内で1位になる割合は41.13%、40.86%だった。これらは採集した比較群での模倣成績であり、到達可能性の正答率や探索成功率ではない。

学習の詳細、元棋譜、ハッシュ、勾配検査、再現コマンドは [TRAINING.md](TRAINING.md) に記録した。NumPyから出力した重みとRustの推論を32局面で照合し、評価値の最大絶対誤差は約 $5.33\times10^{-15}$ だった。[照合結果](parity_verification.json)にモデルのSHA-256も含めた。

その後、学習に使っていない60局面で探索方式を3反復比較した。両モデルとも、ビームの `UNKNOWN` をGBFSに渡すと29件を証明した。各段階の独立測定時間を加算した中央値は線形7.604秒、ネットワーク7.845秒だった。事前に定めた規則により線形モデルを選び、最終評価前にモデル・探索設定・ソース・実行ファイルの指紋を固定した。この選択段階でも、GBFS単独に対する総時間・生成数の改善は確認できなかった。

- [事前の実験計画](experiment_plan.json)には、データ、比較対象、選択規則を記録した。
- [モデル選択](model_selection.json)には、60局面での測定に基づく選択理由を記録した。
- [固定した設定](frozen_settings.json)には、最終評価前の日時と各ハッシュを記録した。

## 比較条件

すべて標準初期配置、`exact`、前向き境界8石、1スレッドで測定した。ビーム幅は32とし、学習した評価は既存の石数優先順位の中で候補を比較するために使った。幅制限なしの比較も、同じ石数優先順位と学習評価を使うbest-first探索であり、通常のGBFSと同じ優先順位ではない。

GBFSの上限100,000は登録局面数、ビームと幅制限なしの学習探索の上限100,000は生成候補数である。**同じ数値を同じ単位の予算として扱っていない。** 仕事量の比較には、重複や必要条件による棄却を含む共通の「生成数」と、候補列挙を開始した「展開数」を使う。二段法では、ビームが `UNKNOWN` とした入力だけを、GBFS単独と同じ条件で後段に渡す。

最終評価には次の3群を用いた。最終結果を使ったモデル、幅、予算の変更は行っていない。

| 入力 | 内容 |
|---|---|
| 独立144局面 | 新しい乱数種20261127で合法な対局から生成した。16、24、32、40、48、56石を各24件含む。 |
| 過去の残存58局面 | 前回の実験と同じ全58件を使った。過去の `UNKNOWN` は正解ラベルではなく、この群も新しい独立テストとは呼ばない。 |
| 新しい残存8局面 | 乱数種20261128でexact母集団から2,000件を抽出し、必要条件を通過した8件をSATの `placement-columns` 符号化で各1秒処理した。残った8件をすべて使った。 |

学習用・学習検証用の正規化キー107,795件と、各評価目標との重複は0だった。144局面の生成では、重複による置換も0件だった。既知の合法局面を `NG` とした場合は、ベンチマーク自体をエラーにする。各方式の実行順を局面・反復に応じてずらし、計測中に学習やコンパイルは行わなかった。

## 独立144局面の結果

生成数と展開数は1反復分で、判定とカウンタは3反復で一致した。時間は各反復の探索時間の合計の中央値である。モデル推論と探索内の棋譜再生を含み、共有の前向き表構築と追加の独立検証は含まない。

| 手法 | 到達可能と証明した局面 | 生成数 | 展開数 | 探索時間 |
|---|---:|---:|---:|---:|
| GBFS | 75 / 144 | 21,428,617 | 7,453,998 | 18.560秒 |
| 手作りmobilityビーム | 39 / 144 | 991,103 | 319,426 | 0.527秒 |
| 線形モデルのビーム | 35 / 144 | 501,328 | 112,761 | 0.388秒 |
| ネットワークのビーム | 36 / 144 | 537,257 | 128,515 | 1.221秒 |
| 線形モデル、幅制限なし | 59 / 144 | 9,334,863 | 2,761,393 | 6.446秒 |
| ネットワーク、幅制限なし | 63 / 144 | 8,963,450 | 2,688,965 | 18.996秒 |

線形ビームの推論時間は0.122秒、ネットワークのビームは0.913秒だった。推論時間は表の探索時間の内数である。候補を少なく生成して早く終了していても、単独ビームの成功数はGBFSより少ないため、その時間差を同じ問題に対する性能向上とは解釈しない。

選択した線形ビームの未解決109件をGBFSに渡すと、**GBFSの全75成功を維持して76成功となった。** 追加は40石のcase 79であり、合法棋譜付きの入力をGBFSが指定予算内には解けなかった例である。手作りmobilityビームの前段には追加成功がなかった。

| 二段法 | 到達可能と証明した局面 | 生成数 | GBFS比 | 展開数 |
|---|---:|---:|---:|---:|
| 線形ビーム → GBFS | 76 / 144 | 21,328,142 | 0.99531 | 7,340,701 |
| ネットワークのビーム → GBFS | 75 / 144 | 21,797,581 | 1.01722 | 7,519,116 |
| 線形、幅制限なし → GBFS | 79 / 144 | 28,848,510 | 1.34626 | 9,490,518 |
| ネットワーク、幅制限なし → GBFS | 81 / 144 | 27,457,758 | 1.28136 | 9,065,183 |

選択した二段法の生成数は0.4689%、展開数は1.5200%減った。幅制限を外すと追加で解ける局面は増えたが、生成数と時間も大きく増える。幅制限なしの二段法の推計時間は、線形で25.7%、ネットワークで89.1%増えた。この結果を使って選択モデルや運用方針を変更していない。

[生データ](holdout.csv)、[集計](holdout_report.json)、[全成功証跡](holdout_records.csv)、[独立検証](holdout_independent_verification.json)を保存した。

## 残存集合の結果

過去58件では全方式が `UNKNOWN` だった。線形ビームを前段に置くと、GBFSの17,018,567生成に211,635生成が追加され、二段法は17,230,202生成となった。増加率は1.2436%で、追加の到達可能証明はなかった。

新しい8件では、GBFSが0件を `OK`、5件を `NG`、3件を `UNKNOWN` とした。**学習探索はすべての設定で、0件の `OK`、0件の `NG`、8件の `UNKNOWN` だった。** 二段法の5件の `NG` は後段の既存GBFSによるものであり、学習出力から作った判定ではない。二段法の生成数は1,024,316で、GBFSの1,007,379から1.6813%増えた。追加の到達可能証明はなかった。

5件の `NG` はいずれもGBFSが予算内に探索を完全に終えた結果だった。判定を交差確認するため、性能測定とは別にSATを各30秒で実行し、`ply` 符号化で3件、残り2件を `placement-columns` 符号化で `UNSAT` と確認した。矛盾する `SAT` はなかった。[交差確認の記録](ng_crosscheck/summary.json)に入力、探索数、ソルバの結果を保存した。これは別方式との結果の一致であり、DRAT/LRAT等のUNSAT証明を独立した証明検査器に通したものではない。

新しい残存集合は8件と小さいため、この結果をすべての実入力へ一般化しない。一方、合法な対局から得た144件での追加1成功だけを根拠に、実際の残存集合でも有効と主張することはできない。

[過去58件の集計](legacy_sat_report.json)、[新しい8件の集計](sampled_sat_report.json)、[入力の由来](evaluation_provenance.json)に詳細を記録した。

## 実際のCLI全体の時間

選択した線形モデルについて、`reverse_search learned-beam` が出力した未確定ファイルを、実際に `gbfs-parallel` へ渡した。プロセス起動、前向き表構築、モデル読込み、探索、結果書出しを含む時間を測定した。外部の追加検証は計測外である。方式の実行順を反復ごとに交互にし、各入力の多重度、既存の確定結果、証跡を検査した。

| 入力 | GBFSの OK / NG / UNKNOWN | 線形ビーム → GBFS | GBFSの時間 | 二段法の時間 |
|---|---|---|---:|---:|
| 独立144局面 | 75 / 0 / 69 | 76 / 0 / 68 | 19.120秒 | 18.986秒 |
| 過去58局面 | 0 / 0 / 58 | 0 / 0 / 58 | 13.830秒 | 13.325秒 |
| 新しい8局面 | 0 / 5 / 3 | 0 / 5 / 3 | 0.740秒 | 0.796秒 |

時間は3反復の中央値である。144局面では中央値が0.70%短かったが、各反復の差は約−0.134秒、+0.558秒、−0.638秒と増減が混在した。安定した高速化とは判断しない。

過去58件でも実CLIの中央値は二段法の方が短いが、後段GBFSの登録局面数は同じであり、前段の生成候補が追加されている。独立計測の時間を足した推計では、二段法は1.35%長い。実行方式や測定時の条件を含む時間差の原因を、この実験だけでは特定していない。少数の時間測定だけから、学習による探索量削減や汎用的な高速化を主張しない。

各反復は [144局面](holdout_pipeline.csv)、[過去58件](legacy_sat_pipeline.csv)、[新しい8件](sampled_sat_pipeline.csv) に保存した。

## 検証と記録の完全性

`cargo test --release --locked --offline` で208件が成功した。学習評価を意図的に悪化させる4モデル、幅1と幅制限なしを使い、独立した配列実装で得た548個のexact問い合わせに対する合計4,384探索を検査した。誤った `OK` と学習由来の `NG` はなかった。境界不一致、予算0、パス、終局、標準初期配置以外の拒否、不正モデル、最大許容重み、CLI、推計処理への引継ぎも検査した。[検証記録](verification.json)と[独立レビュー](soundness_review.json)を参照。

探索選択用60局面の成功351件、最終144局面の成功921件、実CLIの成功453件を、対応する入力と結び付けて独立再生した。元棋譜は学習用・学習検証用1,200件に加え、探索選択用60件、最終144件を検証した。成功0件の残存集合も、結果表と証跡0件が一致することを確認した。

初回の144局面の測定では、結果表の921件の `OK` に対して606証跡しか保存されていなかった。保存済みの証跡自体は合法だったが、全成功の外部検証ができないため、この測定の時間は主結果に使っていない。元ファイルは [不完全な記録の保存先](incomplete_capture/20261025T142235Z/) に未加工で残した。ファイルの置換と整合する時刻・inodeの変化を観測したが、直接の原因は特定していない。

対策として、[専用の収集スクリプト](../../scripts/capture_learned_benchmark.py)で、作業ディレクトリ外への出力、探索プロセスの完了、全 `OK` と証跡の件数照合、独立再生、ハッシュを照合した保存を順に行い、完了マーカーを最後に記録した。検証器も、同じバイト列を読み取って検証とハッシュ計算を行うようにした。モデルと探索コードは変更せず、144局面を同条件で再測定し、残る2群と実CLI測定も同じ収集手順で実施した。

初回と再測定は全2,592行の時間3列以外で一致し、元局面と元棋譜のハッシュも一致した。旧606証跡は新921証跡の厳密な先頭部分だった。[再現照合](capture_reproduction_verification.json)と、各群の `*_capture.json` に完全な記録のハッシュを保存した。本報告の最終結果には、この収集手順の検証を通過した測定だけを使っている。[実行環境](environment.json)と[保存ファイルの指紋](artifact_manifest.json)も記録した。

## 再現方法

コミット済みモデルを使う探索にはPythonや学習ライブラリは不要である。

```sh
cargo build --release --locked
cargo test --release --locked

cargo run --release --bin reverse_search -- \
  learned-beam research/learned_beam/holdout_positions.txt \
  --mode exact --discs 8 --max-nodes 100000 --beam-width 32 \
  --model research/learned_beam/models/linear.json \
  --out-dir /tmp/othello-learned-output

python3 scripts/verify_records_independent.py \
  /tmp/othello-learned-output/reverse_exact_records.csv \
  --positions research/learned_beam/holdout_positions.txt
```

推計パイプラインでも、`estimate reverse-search --from <前段> --out-dir <出力> learned-beam --discs 8 --max-nodes 100000 --beam-width 32 --model <モデル>` として使える。学習段の `UNKNOWN` を次の既存探索へ渡せる。モデルのSHA-256と判定方針を実行結果に保存する。

学習と正規化キーの再生成は [TRAINING.md](TRAINING.md) の手順に従う。そこに示す `/tmp/reverse-ranker-data` にキーを生成した後、次のコマンドで、リポジトリに保存した2モデルと再生成したキーを使って固定した最終評価を収集できる。既存成果物を上書きしないよう、別の出力先を指定する。

```sh
python3 scripts/capture_learned_benchmark.py \
  --exclude-keys /tmp/reverse-ranker-data/train_keys.txt \
  --exclude-keys /tmp/reverse-ranker-data/validation_keys.txt \
  --output-dir /tmp/othello-learned-reproduction

python3 scripts/report_learned_benchmark.py \
  research/learned_beam/holdout.csv --output /tmp/holdout_report.json
```

## 解釈

今回の学習には、GBFSが予算内に発見できなかった経路を選ぶ補完性があった。ただし、幅32のビーム単独では多くの合法局面を取りこぼした。ネットワークは線形モデルより順位損失が小さく、ビーム単独の成功も1件多かったが、幅32の二段法では推論コストに見合う改善を得られなかった。幅制限なしでは追加成功が増えたが、その分の計算量も増えた。

この結果は、1,000棋譜による観測前駆の順位学習、2種類の軽量モデル、固定した幅・境界・予算についての結果である。学習方式全般の限界を示すものではない。次の検討対象としては、実際の探索で訪れる難しい候補からの追加学習、予算内成功を直接扱う学習目標、有望な逆着手を先に生成する方法が考えられるが、いずれも本実験で効果を検証した手法ではない。

現時点では、確定判定の根拠を証明棋譜と従来の厳密手法に限定したまま、実験用の探索選択肢として扱う。
